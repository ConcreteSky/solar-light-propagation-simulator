# Machine-learning surrogate model

## Purpose

Model version 1.0.0 is a local scikit-learn surrogate for the deterministic educational physics engine. It approximates four numerical outputs quickly; it does not replace the physics baseline, retrieve astronomical facts, establish observational accuracy, or generate text or images.

The deterministic `/api/analyze/{destinationId}` endpoint remains authoritative. `/api/predict/{destinationId}` always compares the ML output with that baseline and falls back to it when model inference is unsafe.

## Dataset and split

Training uses `data/training/light_training_data.csv`, generated by deterministic physics generator 1.0.0 with seed 741. It contains 10,000 synthetic, non-duplicated rows. Real Solar System bodies are excluded from training and retained as benchmark cases.

The generator's predefined split is preserved:

- 8,000 training rows;
- 1,000 validation rows for candidate selection;
- 1,000 untouched test rows for final reporting.

This differs from the optional 70/15/15 suggestion because Session 3 already established a reproducible 80/10/10 contract. Additional test groups cover inner-system, outer-system, dense-atmosphere, and airless conditions.

## Inputs

The ordered feature contract is:

1. distance from the Sun, km;
2. incoming solar irradiance, W/m²;
3. atmosphere-present Boolean;
4. surface pressure, Pa;
5. atmospheric density, kg/m³;
6. CO2 fraction;
7. N2 fraction;
8. O2 fraction;
9. CH4 fraction;
10. H2 fraction;
11. He fraction.

Distance, irradiance, pressure, and density receive `log(1 + x)` transformation and standard scaling. Remaining features receive standard scaling. A median imputer is packaged in the pipeline for technical consistency, but API inference rejects missing core scientific fields before preprocessing and uses deterministic fallback instead. It never presents imputed values as measured facts.

An unreported individual gas has zero optical contribution, matching the documented Session 3 convention. An atmosphere with entirely unavailable composition is not eligible for ML inference.

Distance and irradiance are physically related and therefore redundant. Both remain in version 1.0.0 because both are supported inputs, and the measured tree-model results were stable. Future feature-ablation work should be versioned rather than silently changing this contract.

## Targets

The regressors approximate:

- transmitted fraction;
- scattered fraction;
- absorbed fraction;
- relative brightness.

Dominant color is still produced by the deterministic broad-color rules using the validated ML fractions and brightness. Apparent Sun size is copied from the deterministic distance rule. No color classifier or generative model is trained.

## Candidates and selection

Training compares:

- Linear Regression;
- Random Forest Regressor with 160 trees, depth 18, and minimum leaf size 2;
- four HistGradientBoosting regressors through `MultiOutputRegressor`, with 180 iterations, learning rate 0.08, 31 leaf nodes, and L2 regularization 0.05.

The fixed seed is 741. The selection rule chooses the lowest validation mean MAE; candidates within 2% are resolved in favor of the smaller serialized model. HistGradientBoosting was selected. The final pipeline was refit on the combined 9,000 training and validation rows, then evaluated once on the untouched test split.

The saved artifact is `backend/models/light_model.joblib`. It contains the preprocessing pipeline, estimator, feature order, target order, model name, model version, seed, and generator version. Human-readable metadata is stored beside it.

## Output validation and fallback

Raw ML predictions are never returned unchecked.

- Non-finite or incorrectly shaped output triggers fallback.
- A fraction outside `[-0.1, 1.1]`, brightness outside that range, or energy-sum error over 0.1 is a serious violation and triggers fallback.
- Smaller excursions are clamped to `[0, 1]`, and the three energy fractions are normalized to sum to one.
- The response reports whether correction or fallback occurred.

Fallback also occurs when the model file is absent or incompatible, atmosphere state is unknown, pressure/density is missing, or atmospheric composition is wholly unavailable. The response method becomes `deterministic_fallback`; deterministic output is never mislabeled as an ML prediction.

## API

Start the backend normally, then request:

```text
GET /api/predict/mars
```

The response includes the destination, method, model identity, validated results, correction/fallback state, absolute differences from the deterministic baseline, and source IDs. Existing `/api/analyze/{destinationId}` behavior is unchanged. The model is preloaded during FastAPI startup and cached for subsequent requests.

## Retraining

From `backend/`:

```powershell
.\.venv\Scripts\python.exe training\train_model.py
.\.venv\Scripts\python.exe training\evaluate_model.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Regenerate the Session 3 dataset first only when the deterministic physics model or generator version changes. Never tune candidates using the test split. Commit the regenerated model, metadata, and evaluation JSON together.

## Scientific limitations

The synthetic labels inherit every limitation documented in `PHYSICS_MODEL.md`. Excellent surrogate metrics mean that the ML model reproduces that code; they do not show that either system matches real atmospheric observations. The local catalog has no independent measurements matching the aggregate transmitted/scattered/absorbed convention, so no observational validation was performed.

Because HistGradientBoosting fits outputs independently, nearly every tested row needed small energy normalization. No serious consistency failures occurred. The API therefore treats normalization as a required part of this model version, not as evidence of independent physical understanding.
